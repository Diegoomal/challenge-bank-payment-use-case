Scenario 02 - failure in last step: issue receipt

Goal:
Validate that payment confirmation and notifications succeed even when receipt
issuing does not run. This simulates the last post-confirmation step being down.

Preparation:

docker compose up -d --build
docker compose stop issue_receipt_consumer

curl -X POST http://localhost:8080/api/v1/accounts -H "Content-Type: application/json" -d '{"customer_id":"scenario-02-customer","account_holder":"Scenario 02 Customer","initial_deposit":"100.00"}'

docker compose exec -T debit_account_service python -c "from decimal import Decimal; from adapters.persistence.sqlite_account_repository import SQLiteAccountRepository; from domain.account import Account; r=SQLiteAccountRepository('/data/debit_account.db'); a=r.get_by_customer_id('scenario-02-customer') or Account.create(customer_id='scenario-02-customer', holder_name='Scenario 02 Customer', balance=Decimal('100.00')); r.save(a); print(a.id, a.customer_id, a.balance)"

docker compose exec -T credit_account_service python -c "from decimal import Decimal; from adapters.persistence.sqlite_account_repository import SQLiteAccountRepository; from domain.account import Account; r=SQLiteAccountRepository('/data/credit_account.db'); a=r.get_by_customer_id('scenario-02-merchant') or Account.create(customer_id='scenario-02-merchant', holder_name='Scenario 02 Merchant', balance=Decimal('0.00')); r.save(a); print(a.id, a.customer_id, a.balance)"

Action:

curl -X POST http://localhost:8080/api/v1/payments/start -H "Content-Type: application/json" -d '{"customer_id":"scenario-02-customer","merchant_id":"scenario-02-merchant","amount":"50.00","payment_method":"ACCOUNT_BALANCE"}'

Wait a few seconds, then inspect the result:

docker compose exec -T confirm_payment_service python -c "import sqlite3; c=sqlite3.connect('/data/confirm_payment.db'); print(c.execute('select id, customer_id, merchant_id, status, confirmed_at from transactions where customer_id=? order by updated_at desc limit 5', ('scenario-02-customer',)).fetchall())"
docker compose exec -T notify_merchant_service python -c "import sqlite3; c=sqlite3.connect('/data/notify_merchant.db'); print(c.execute('select transaction_id, merchant_id, status from notifications where merchant_id=? order by notified_at desc limit 5', ('scenario-02-merchant',)).fetchall())"
docker compose exec -T notify_customer_service python -c "import sqlite3; c=sqlite3.connect('/data/notify_customer.db'); print(c.execute('select transaction_id, customer_id, status from notifications where customer_id=? order by notified_at desc limit 5', ('scenario-02-customer',)).fetchall())"
docker compose exec -T issue_receipt_service python -c "import sqlite3; c=sqlite3.connect('/data/issue_receipt.db'); print(c.execute('select transaction_id, customer_id, merchant_id, status from receipts where customer_id=? order by issued_at desc limit 5', ('scenario-02-customer',)).fetchall())"
docker compose logs --no-color --tail=120 issue_receipt_consumer

Recovery check:

docker compose start issue_receipt_consumer
docker compose logs --no-color --tail=120 issue_receipt_consumer
docker compose exec -T issue_receipt_service python -c "import sqlite3; c=sqlite3.connect('/data/issue_receipt.db'); print(c.execute('select transaction_id, customer_id, merchant_id, status from receipts where customer_id=? order by issued_at desc limit 5', ('scenario-02-customer',)).fetchall())"

Expected behavior:

- Payment reaches CONFIRMED.
- Merchant and customer notifications are delivered.
- Receipt is absent while issue_receipt_consumer is stopped.
- After issue_receipt_consumer starts again, RabbitMQ can deliver the pending payment.confirmed message and the receipt becomes ISSUED.

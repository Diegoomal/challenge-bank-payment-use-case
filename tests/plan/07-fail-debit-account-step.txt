Scenario 07 - failure in debit account step

Goal:
Validate business failure during debit. The payment should be reversed and
post-confirmation services must not run.

Preparation:

docker compose up -d --build

Create the public account, but do not seed debit_account_service. This keeps
the debit service unable to find the account projection.

curl -X POST http://localhost:8080/api/v1/accounts -H "Content-Type: application/json" -d '{"customer_id":"scenario-07-customer","account_holder":"Scenario 06 Customer","initial_deposit":"100.00"}'

Action:

curl -X POST http://localhost:8080/api/v1/payments/start -H "Content-Type: application/json" -d '{"customer_id":"scenario-07-customer","merchant_id":"scenario-07-merchant","amount":"50.00","payment_method":"ACCOUNT_BALANCE"}'

Wait a few seconds, then inspect the result:

docker compose exec -T start_payment_service python -c "import sqlite3; c=sqlite3.connect('/data/start_payment.db'); print(c.execute('select id, customer_id, merchant_id, amount, status from transactions where customer_id=? order by created_at desc limit 5', ('scenario-07-customer',)).fetchall())"
docker compose exec -T debit_account_service python -c "import sqlite3; c=sqlite3.connect('/data/debit_account.db'); print('accounts=', c.execute('select customer_id, balance from accounts where customer_id=?', ('scenario-07-customer',)).fetchall()); print('outbox=', c.execute('select event_name, routing_key, status, payload from outbox_events order by created_at desc limit 5').fetchall())"
docker compose exec -T confirm_payment_service python -c "import sqlite3; c=sqlite3.connect('/data/confirm_payment.db'); print(c.execute('select id, customer_id, merchant_id, status, confirmed_at from transactions where customer_id=? order by updated_at desc limit 5', ('scenario-07-customer',)).fetchall())"
docker compose exec -T reverse_payment_service python -c "import sqlite3; c=sqlite3.connect('/data/reverse_payment.db'); print(c.execute('select id, customer_id, merchant_id, status, reversal_reason from transactions where customer_id=? order by updated_at desc limit 5', ('scenario-07-customer',)).fetchall())"
docker compose exec -T notify_merchant_service python -c "import sqlite3; c=sqlite3.connect('/data/notify_merchant.db'); print(c.execute('select transaction_id, merchant_id, status from notifications where merchant_id=? order by notified_at desc limit 5', ('scenario-07-merchant',)).fetchall())"
docker compose exec -T notify_customer_service python -c "import sqlite3; c=sqlite3.connect('/data/notify_customer.db'); print(c.execute('select transaction_id, customer_id, notification_type, status from notifications where customer_id=? order by notified_at desc limit 5', ('scenario-07-customer',)).fetchall())"
docker compose exec -T issue_receipt_service python -c "import sqlite3; c=sqlite3.connect('/data/issue_receipt.db'); print(c.execute('select transaction_id, customer_id, merchant_id, status from receipts where customer_id=? order by issued_at desc limit 5', ('scenario-07-customer',)).fetchall())"

Expected behavior:

- start_payment_service starts the transaction.
- debit_account_service publishes debit.failed with ACCOUNT_NOT_FOUND.
- reverse_payment_service marks the transaction as REVERSED.
- confirm_payment_service does not confirm the transaction.
- notify_customer_service delivers a PAYMENT_REVERSED customer notification.
- Merchant success notification and receipt are absent.
